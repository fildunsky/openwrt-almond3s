# Метрики модема на Almond: что берём из телеметрии 5gmodem

Модемные метрики **не собираем сами** — ни вызовов `5gmodem.sh`, ни чтения его
внутренних снимков `/tmp/5gmodem_metrics_*`. Единственный источник — телеметрия
самого 5gmodem (появилась в 2.4.22):

```
/tmp/5gmodem_tele.json        публикуемое состояние (сигнал, оператор, режим, ca, скорости, sms)
/tmp/5gmodem_tele_cell.json   детали соты и несущих — ТОЛЬКО локально, наружу не отдавать
```

## Общие правила — в каноне, не здесь

Формат полей, правила для потребителя (нет ключа = нет данных, свежесть по
mtime с порогом 90 секунд, запрет кэшировать поверх, частота чтения, один
публикатор MQTT), смысл активной и спящей агрегации, четыре способа забора —
всё это описано один раз в репозитории 5gmodem:

**[luci-app-5gmodem/docs/telemetry.md](https://github.com/fildunsky/luci-app-5gmodem/blob/master/docs/telemetry.md)**

Дублировать сюда не будем: два документа неизбежно разъезжаются, и мы это уже
проходили. Ниже — только то, что относится к Almond и в канон не помещается.

## Разделение ролей на Almond

| Кто | Пишет | Куда |
|---|---|---|
| 5gmodem | модемные поля | `/tmp/5gmodem_tele.json` |
| Наш агрегатор | `batt chg cpu mem disk up wifi vpn vpn_node` | `/tmp/almond_tele.json` |

Каждый пишет только своё. Потребители (LCD, Zigbee-мост, MQTT) **сливают оба
файла**; при совпадении ключей модемные значения берутся из файла 5gmodem.

**Публикатор MQTT на Almond — наш агрегатор.** Собственный паблишер 5gmodem
здесь НЕ настраивать (не задавать `5gmodem.tele.mqtt_host`), иначе в Home
Assistant появятся два устройства с пересекающимися сенсорами.

## Чек-лист для наших потребителей

- [ ] LCD-страницы (`ui.uc`, виджеты) читают модемные метрики из файлов
      телеметрии; прямые вызовы 5gmodem-скриптов удалены.
- [ ] Zigbee-мост (`almond3s-zig.c`, массив `TELE`): маппинг сверен с полями
      канона; идентификаторы 0x01..0x10 не разъехались с числом полей, для
      строкового `ca` выделен свой.
- [ ] Правило «нет ключа = нет данных» соблюдено во всех трёх потребителях
      (экран, TLV, MQTT).
- [ ] Свежесть по mtime реализована; состояние «модем вынут» показано осмысленно.
- [ ] MQTT публикует объединённый JSON одной темой состояния; discovery — от
      одного устройства.
- [ ] Системная телеметрия Almond пишется своим файлом по тем же правилам.
- [ ] Индикатор агрегации на экране = `ca` из основного файла (или `nca >= 1`),
      а НЕ «есть слоты `s1..s4`»: слоты описывают и спящие несущие. Спящий слот
      в детальной таблице показывать резервом, приглушённо.
- [ ] Экран читает не чаще раза в 2–5 секунд.

## Решённые вопросы (история, чтобы не возвращаться)

**Обрезанный файл (20.08.2026).** Экспортёр публиковал снимок и с пустым
сигнальным ядром, когда AT-порт был занят. Исправлено на стороне 5gmodem:
осечка опроса больше не публикуется, прежние файлы остаются нетронутыми.
Контракт «свежий файл без модемных полей = модема нет» снова строгий. Наш
запас в три пустых чтения можно оставить ремнём безопасности; расширенный
признак наличия модема (`sig` ИЛИ `rsrp` ИЛИ `oper`) — правильный.

**Детали соты (20.08.2026).** Весь набор страницы отдаётся в
`/tmp/5gmodem_tele_cell.json`, прямые вызовы убраны. Помнить: `mnc` — строка
(ведущий ноль значащий), `phone` допущен только в этом локальном файле,
витринные строки показывать как есть.

**Агрегация «всегда есть» (22.08.2026).** Коллектор судил по наличию слотов.
Разбор и правило — в каноне, раздел «Агрегация: активная и спящая несущая».

## Отладка на устройстве

```sh
cat /tmp/5gmodem_tele.json                  # что отдаёт 5gmodem
/usr/share/5gmodem/telemetry.sh write       # пересобрать прямо сейчас
date -r /tmp/5gmodem_tele.json              # свежесть
```
