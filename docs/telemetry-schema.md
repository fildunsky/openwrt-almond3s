# Единый формат телеметрии Almond

Документ для тех, кто отдаёт метрики наружу: на экран, соседям по Zigbee и в
умный дом. Цель простая — чтобы поле «уровень сигнала» называлось одинаково во
всех наших программах и не требовало переводчика на каждой границе.

## 1. Правила

* **Имя поля** — короткое, латиницей, в нижнем регистре, без префиксов
  программы: `sig`, а не `modem_signal_level`.
* **Единица зашита в поле**, а не в значение: проценты — целое 0..100, dBm —
  целое со знаком, температура — целые °C. Никаких «-97 dBm» строкой.
* **Отсутствие данных — это `null` или отсутствие ключа**, но не `0` и не
  `-1`. Ноль значит настоящий ноль. Протухший источник (модем вынут, интерфейс
  лежит) — это тоже «нет данных»: поля убираются из файла, а не замораживаются
  на последнем значении; живость самого экспортёра читатель проверяет по mtime.
* **Дробные значения округляются к ближайшему целому** (не floor и не trunc) —
  иначе два экспортёра дадут разные цифры из одного источника.
* **Скорости (`rx`/`tx`) считаются из дельты счётчиков между двумя записями
  файла** — окно усреднения равно интервалу записи; первая запись после старта
  полей скорости не содержит.
* **Идентификаторы не входят в телеметрию**: IMEI, IMSI, ICCID, номера
  телефонов, ключи — никогда. Файл должен быть безопасен для отдачи наружу.
* Числа — числами, без кавычек. Строки — только там, где значение
  действительно текст (оператор, имя узла VPN).
* Обновление — не чаще раза в секунду и не реже раза в минуту.

## 2. Канонические поля

| Поле | Тип | Единица | Смысл |
|---|---|---|---|
| `sig` | 0..100 | % | Качество сотового сигнала, сведённое к процентам |
| `oper` | строка | — | Имя оператора, как его отдаёт сеть |
| `rsrp` | int | dBm | Мощность опорного сигнала |
| `rsrq` | int | dB | Качество опорного сигнала |
| `sinr` | int | dB | Отношение сигнал/шум |
| `band` | строка | — | Первичная несущая одним токеном, например `B7` |
| `ca` | строка | — | Активная агрегация: `B3+B7+n78`, PCC первым; поля нет, если несущая одна |
| `mode` | строка | — | Тип сети: `4G`, `4G+`, `5G NSA` |
| `temp` | int | °C | Температура модема |
| `batt` | 0..100 | % | Заряд батареи |
| `chg` | 0/1 | — | Идёт ли зарядка |
| `cpu` | 0..100 | % | Загрузка процессора |
| `mem` | 0..100 | % | Занятая память |
| `disk` | 0..100 | % | Занятое место в оверлее |
| `up` | int | мин | Аптайм |
| `wifi` | int | шт | Клиентов Wi-Fi |
| `ping` | int | мс | Задержка до контрольного узла |
| `rx`, `tx` | int | Б/с | Текущая скорость |
| `sms` | int | шт | Непрочитанных сообщений |
| `vpn` | 0/1 | — | Туннель поднят |
| `vpn_node` | строка | — | Имя выбранного узла VPN |

Расширять список можно, но новое поле сначала попадает сюда, а уже потом в код.

## 2.1 Детальные поля соты (необязательные)

Эти поля нужны странице «Сота/Сеть» на экране. Они необязательны: экспортёр
может их не отдавать, и тогда страница показывает прочерки. Правила те же —
нет ключа значит нет данных.

| Поле | Тип | Единица | Смысл |
|---|---|---|---|
| `pci` | int | — | Physical Cell ID обслуживающей соты |
| `earfcn` | int | — | Номер частотного канала обслуживающей несущей |
| `enb` | int | — | Идентификатор базовой станции (eNB/gNB) |
| `cid` | int | — | Идентификатор соты |
| `tac` | int | — | Код зоны отслеживания |
| `apn` | строка | — | Активная точка доступа |
| `wan_ip` | строка | — | Адрес, выданный оператором |
| `modem` | строка | — | Модель модема |
| `nbrs` | массив | — | Соседние соты: `[{"band":"B7","pci":94,"rsrp":-104,"rsrq":-12}]` |
| `mcc` | int | — | Serving MCC |
| `mnc` | строка | — | Serving MNC; строкой — ведущий ноль значащий (250-02 ≠ 250-2) |
| `lac` | int | — | Location Area Code |
| `cid_hex` | строка | — | Идентификатор соты в hex |
| `bandwidth` `txpower` `uecat` `volte` `mimo` `rxdiv` `antports` `therm` `fw` | строка | — | Витринные значения экспортёра как есть |
| `pathloss` `cqi` `csq` `rssi` `conn_time` `simslot` `roaming` `nca` | int | — | Числовые детали (conn_time — с, nca — активных SCC) |
| `s1band`..`s4state` | — | — | Несущие агрегации по слотам |
| `phone` | строка | — | Номер SIM. Идентификаторы допустимы ТОЛЬКО в файле-приложении |

Три ограничения. Детальные поля живут **отдельным файлом-приложением**
`/tmp/<программа>_tele_cell.json`, а не в основном: основной файл публикуемый,
а идентификаторы соты локализуют положение устройства. По Zigbee эти поля
**не передаются**: кадр вмещает около 60 байт, а детали соты интересны только
на самом устройстве. В MQTT они **не публикуются вовсе** (не только `wan_ip`) —
файл-приложение читает только локальный экран.

## 3. Где это лежит

**Локально:** JSON-файл, который переписывается целиком (пишем во временный и
переименовываем — читатель никогда не увидит половину файла):

```
/tmp/<программа>_tele.json
{"sig":70,"oper":"Megafon","rsrp":-104,"batt":65,"cpu":7,"up":329,"vpn":1}
```

**По Zigbee (Almond):** те же поля упакованы в TLV — по байту на
идентификатор, байту на длину и значение младшим байтом вперёд. Строки
передаются как есть. Таблица идентификаторов — в `almond3s-zig.c`, массив
`TELE` (числа) и `TELE_STR` (строки); занятые: `0x01..0x16`.

| ID | Поле | | ID | Поле | | ID | Поле |
|---|---|---|---|---|---|---|---|
| 0x01 | sig | | 0x09 | wifi | | 0x11 | rsrq |
| 0x02 | rsrp | | 0x0A | ping | | 0x12 | sinr |
| 0x03 | batt | | 0x0B | sms | | 0x13 | band |
| 0x04 | chg | | 0x0C | rx | | 0x14 | ca |
| 0x05 | cpu | | 0x0D | tx | | 0x15 | mode |
| 0x06 | mem | | 0x0E | temp | | 0x16 | vpn_node |
| 0x07 | disk | | 0x0F | vpn | | | |
| 0x08 | up | | 0x10 | oper | | | |

Кадр Zigbee вмещает около 60 байт полезной нагрузки, поэтому набор режется на
части по границам полей и собирается получателем обратно.

## 4. Наружу: MQTT и Home Assistant

Тема состояния — одна на устройство, значения в одном JSON:

```
almond3s/<имя-устройства>/state     {"sig":70,"batt":65,...}
almond3s/<имя-устройства>/available online | offline
```

Автообнаружение Home Assistant — по одной теме на метрику, публикуется однажды
с флагом retain:

```
homeassistant/sensor/<имя>_sig/config
{
  "name": "Уровень сигнала",
  "state_topic": "almond3s/<имя>/state",
  "value_template": "{{ value_json.sig }}",
  "unit_of_measurement": "%",
  "device_class": "signal_strength",
  "availability_topic": "almond3s/<имя>/available",
  "unique_id": "<имя>_sig",
  "device": { "identifiers": ["<имя>"], "model": "Almond 3S", "manufacturer": "Securifi" }
}
```

Соответствие классов: `sig`/`rsrp` → `signal_strength`, `batt` → `battery`,
`temp` → `temperature`, `rx`/`tx` → `data_rate`, `ping` → `duration`.
Для `vpn` и `chg` — `binary_sensor` с `payload_on: 1`.

**Реализация на Almond:** служба `almond3s-mqtt` (свой клиент MQTT 3.1.1 без
внешних зависимостей). Она и есть единственный публикатор: сливает
`/tmp/almond_tele.json` и `/tmp/5gmodem_tele.json` (модемный — с проверкой
свежести), шлёт состояние одной темой, темы автообнаружения с `retain` один раз
за подключение и `offline` завещанием при обрыве. Настройка:

```sh
uci set almond3s.mqtt.enabled='1'
uci set almond3s.mqtt.host='192.168.1.10'   # адрес брокера
uci set almond3s.mqtt.port='1883'
uci set almond3s.mqtt.user='' ; uci set almond3s.mqtt.pass=''
uci set almond3s.mqtt.prefix='almond3s'
uci set almond3s.mqtt.period='60'
uci commit almond3s
/etc/init.d/almond3s-mqtt enable ; /etc/init.d/almond3s-mqtt restart
```

Публикатор на устройстве должен быть один: у 5gmodem есть свой, и его на Almond
включать не нужно, иначе в Home Assistant появятся два устройства с
пересекающимися сенсорами.

## 5. Что это даёт

Одинаковые имена означают, что страница на экране, карточка соседа по Zigbee и
датчик в Home Assistant читают один и тот же источник. Добавили поле в таблицу —
оно появилось везде, где нужно, без переговоров между программами.
