# Обновление Zigbee-чипа EM357 на Almond 3S

Заводская прошивка чипа — EmberZNet 5.1.0.0, протокол EZSP версии 4. Его
отвергают на входе и zigbee2mqtt, и ZHA, и homed: они требуют EZSP 8 и выше.
После обновления чип отвечает как EmberZNet 6.7.8.0 / EZSP v8, и эти программы
видят его без оговорок.

Прошивается **по проводу, который уже есть** — по тому же UART, которым чип
подключён к процессору. Ни программатора, ни вскрытия корпуса не нужно.

## Что понадобится

Файл `NCP_USW_ETRX3_USB_678-57k6.ebl` (151 424 байта) из репозитория
`grobasoz/zigbee-firmware`, каталог `EM357`. Он же лежит в нашей сборке:
`/usr/share/almond3s/zigbee/`.

Важно: берите именно этот вариант, а не `NCP_USW_EM357_6710_PCx`. Те собраны
для плат с внешним усилителем и уводят передачу в альтернативный ВЧ-выход,
который на Almond к антенне не подключён — чип будет «передавать в никуда».

## Способ первый: из меню на экране

Настройки → Zigbee → Настройки → кнопка **Прошить**. Дальше предупреждение,
подтверждение и примерно минута с показом процентов. Чип запустится сам,
версия на странице сменится с оранжевой `EZSP v4` на зелёную `EZSP v8`.

## Способ второй: из командной строки

```sh
uci set almond3s.zigbee.beacon=0; uci commit almond3s   # освободить порт
/etc/init.d/almond3s-lcd stop
/usr/libexec/almond3s/almond3s-zig flash /usr/share/almond3s/zigbee/*.ebl 1
/usr/libexec/almond3s/almond3s-zig info                 # ожидаем "ezsp":8
```

## Обратной дороги нет

Заводского образа EmberZNet 5.1 не существует в открытом доступе — он приезжал
из облака производителя, а меню загрузчика умеет только записывать, но не
читать. Сам загрузчик при этом не затрагивается, поэтому неудачная заливка не
превращает чип в кирпич: можно залить образ заново.

## Как отдать чип стороннему софту

Порт `/dev/ttyS2` держит одна программа. Перед запуском homed или zigbee2mqtt
остановите нашу телеметрию:

```sh
uci set almond3s.zigbee.beacon=0; uci commit almond3s
/etc/init.d/almond3s-lcd restart
```

Параметры адаптера: `/dev/ttyS2`, **57600 8N1**, программное управление
потоком, тип адаптера `ezsp`. Сброс — программный, кадром ASH; аппаратных
линий сброса чипа на плате не разведено.

## Одна оговорка, о которой лучше знать заранее

На наших платах измеритель энергии в чипе завышает уровень примерно на 30–40 дБ:
в тишине он показывает −22…−55 дБм вместо −90 и ниже. Из-за этого проверка
занятости канала почти всегда видит «занято», и стек отказывается передавать —
именно поэтому заводской Zigbee на Almond работал через раз.

Лечится это одним значением: порог проверки канала (`EZSP_VALUE_CCA_THRESHOLD`,
идентификатор `0x15`) поднимается с заводских −75 до −20 дБм. Наша утилита
делает это при каждом запуске. Стороннее ПО такой настройки обычно не
предлагает, поэтому при первых опытах возможны отказы передачи вида
«MAC transmit failure» — сопряжение не идёт, сканы пустые. Если так случится,
напишите: в драйвер адаптера добавляется одна строка, выставляющая порог сразу
после подключения, и всё оживает.

Мануфактурный токен порога (`MFG_CCA_THRESHOLD`) на этом чипе через EZSP
недоступен ни в четвёртой версии, ни в восьмой, поэтому сделать настройку
постоянной можно только программатором по колодке J5705.

### Как выставить порог руками

Своей утилитой, когда чип у нас:

```sh
/usr/libexec/almond3s/almond3s-zig cca -20
```

В стороннем ПО на bellows (zigbee2mqtt, ZHA) — одна строка сразу после
подключения адаптера:

```python
import bellows.types as t
await ezsp.setValue(ezsp.types.EzspValueId.VALUE_CCA_THRESHOLD,
                    t.int8s(-20).serialize())
```

В homed то же самое делается отправкой команды `setValue` с идентификатором
`0x15` и одним байтом `0xEC` (это −20 со знаком) после инициализации адаптера.

Значение живёт до сброса чипа, поэтому строку нужно выполнять при каждом
подключении, а не однократно.
